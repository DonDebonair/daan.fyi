# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`daan.fyi` — Daan Debie's personal site. Next.js 14 (Pages Router) + TypeScript + Chakra UI, content authored in MDX, statically generated, deployed on Vercel.

## Commands

```bash
npm install          # runs postinstall: patch-package + chakra-cli token generation
npm run dev          # dev server (hot reload for components; MDX changes force a full page reload)
npm run build        # production build; postbuild runs next-sitemap
npm run start        # serve the production build
npm run type-check   # tsc --noEmit
npm run lint         # next lint
npm run prettier     # format everything in place
npm run theme        # regenerate Chakra theme typings after editing styles/theme.ts
```

Use **npm, not yarn** — `engines.yarn` is deliberately set to an error string.

There is no test suite. `type-check` + `lint` are the verification steps. A husky `pre-commit` hook runs `lint-staged` (eslint --fix + prettier).

## Content model

All content lives in `content/<type>/<slug>.mdx`; the filename _is_ the slug. `ContentType` (`lib/content-utils.ts`) is `'writings' | 'archive' | 'topics' | 'special'`:

-   `writings/` — current blog posts, served at `/writings/[slug]`. Legacy `/blog/:slug` redirects here (`next.config.js`).
-   `archive/` — old posts kept for permalink stability, served at `/archive/[slug]`. Rendered by a simpler page (no topics, no series).
-   `topics/` — optional per-topic preamble MDX; the directory doesn't exist until a preamble is written.
-   `special/` — non-post MDX. `_kitchensink.mdx` is the styling test page at `/_kitchensink`, which reuses the archive article page component.

Frontmatter: `title`, `publishedAt` (ISO date string), optional `summary`, `topics` (string array), `series` (string).

`lib/posts.ts` is the only reader of the content directory — `getPostsFrontMatter` (metadata only, sorted newest-first) vs `getAndSerializePost` / `getPostsWithContent` (full MDX serialization). Prefer the frontmatter-only variant for listings; serializing every post is expensive.

**Series**: any posts sharing a `series` value are grouped; `getSeriesData` collects them (oldest-first) and `SeriesOverview` renders the navigation box on the article page.

**Topics**: derived entirely from post frontmatter by `lib/topics.ts`. Topic pages are served from the **root-level catch-all `pages/[topic].tsx`**, i.e. `/mental-health`, not `/topics/mental-health`. This means a topic name that collides with a top-level page (`about`, `topics`, `writings`, `archive`, `_kitchensink`) will be shadowed by that page — pick topic slugs accordingly.

## MDX pipeline

`lib/mdx.ts` (`serializePost`) is the single serialization entry point; everything that renders MDX goes through it. Notable plugin behaviour:

-   `remark-capitalize` title-cases all headings, using `TITLE_OPTIONS` from `lib/titleCase.ts` for acronym exceptions (`AWS`, `IAM`, `NextJS`, …). Add new acronyms there. The package is **patched** (`patches/remark-capitalize+1.1.0.patch`) so it accepts options at all — patch-package applies this on install.
-   `remark-textr` applies smart typography (curly quotes, em/en dashes, ellipses, arrows). Because of this, prose in `.tsx` files sometimes contains pre-typographied characters (e.g. `I‘m`) to match.
-   `rehype-img-size` reads dimensions from `dir: 'public'`, so MDX images must live under `public/` and be referenced with a root-relative path. `MDXComponents.img` maps them to `next/image`.
-   `mdx-prism` handles syntax highlighting; the actual Prism token colors are hand-written CSS-in-JS in `styles/styles.ts` (global styles), not a Prism stylesheet.

`components/MDXComponents.tsx` maps every HTML element to a Chakra component and exposes the custom components usable inside MDX: `SideNote`, `Asterisk`, `Small`.

## Feeds and sitemap

RSS/Atom/JSON feeds are generated as a **side effect of `getStaticProps` in `pages/index.tsx`** calling `generateMainFeeds()` — the home page must be built for feeds to exist. `lib/feeds.tsx` renders each post's MDX through `ReactDOMServer.renderToStaticMarkup` inside a `ChakraProvider` to produce feed HTML, then rewrites relative URLs to absolute. Output goes to `public/feeds/` (gitignored). Sitemap and `robots.txt` are generated by `next-sitemap` in `postbuild` and are also gitignored; non-production `VERCEL_ENV` gets a `Disallow: /` robots policy.

## Styling

Chakra theme is composed in `styles/theme.ts` from `config`, `styles`, `fonts`, `fontSizes`, `components`. After changing the theme, run `npm run theme` so `chakra-cli` regenerates the token typings that `ThemeTypings`-based props (e.g. in `SideNote`) rely on.

Layout chain: `_app.tsx` (ChakraProvider + `BaseLayout` with NavBar/Footer) → each page wraps its content in `DefaultLayout`, which renders `Meta` (SEO/OG tags) and the 800px content column. Page-level SEO is set by passing `title`/`description`/`type`/`date` props to `DefaultLayout`.

## Conventions

-   Path aliases: `@/components/*`, `@/lib/*`, `@/layouts/*`. `styles/` has no alias — import it relatively.
-   Prettier: 4-space indent, single quotes (double in JSX), 100 columns, ES5 trailing commas.
-   `strict: false` in tsconfig; page components are typed as returning `ReactNode`/`ReactElement`.
-   Everything is statically generated (`getStaticProps` / `getStaticPaths` with `fallback: false`). There are no API routes and no client-side data fetching.
